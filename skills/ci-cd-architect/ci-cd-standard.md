# CI/CD standard

## DELIVERY MODEL

**CICD-001 — Traceable graph.** A repository MUST document or make evident how a source commit becomes a validated artifact and, when applicable, a deployment.

**CICD-002 — Repository classification.** Workflow design MUST be based on actual languages, artifacts, tests, environments, and release consumers. Templates are starting points, not compliance targets.

**CICD-003 — One source revision.** Build, test, scan, attest, publish, and deploy stages MUST refer to the same source revision or a cryptographically identified artifact produced from it.

## TRIGGERS AND TRUST

**CICD-010 — Minimal triggers.** Workflows run only for events and path changes that can affect their result. Scheduled checks exist only for time-dependent risks.

**CICD-011 — Untrusted code.** Pull-request code from untrusted contexts MUST NOT receive repository, cloud, package, or deployment secrets.

**CICD-012 — Concurrency.** Validation SHOULD cancel obsolete runs for the same branch. Releases and deployments MUST prevent unsafe overlap.

**CICD-013 — Time bounds.** Jobs and external operations have explicit timeouts appropriate to their work.

## PERMISSIONS AND SUPPLY CHAIN

**CICD-020 — Least privilege.** Default workflow permissions are read-only. Each job declares only the additional permissions it needs.

**CICD-021 — Immutable third-party code.** External actions SHOULD be pinned by immutable commit SHA for protected workflows. A dependency bot maintains those pins.

**CICD-022 — Dependency ownership.** Versions live in manifests, lock files, container digests, or generated catalogs. Standards and prompts MUST NOT duplicate a current-version matrix.

**CICD-023 — Provenance.** Published artifacts SHOULD have provenance or attestations when supported by the platform and consumer. Signing and verification policy must identify the trust root.

**CICD-024 — Secret minimization.** Prefer short-lived identity federation over stored long-lived credentials. Secrets are scoped to the job and environment that needs them.

## VALIDATION

**CICD-030 — Fast feedback.** Deterministic formatting, lint, schema, compilation, and unit checks run before slower integration and image tests when dependencies allow it.

**CICD-031 — Relevant layers.** Repositories test the layers they ship: source package, compiled binary, container, migration, infrastructure plan, or deployment probe. A green unit suite alone does not validate a container or package.

**CICD-032 — Realistic contracts.** External integrations use contract fixtures, service containers, sandboxes, or live smoke tests with explicit freshness. Pure mocks do not prove compatibility.

**CICD-033 — No hidden failure.** A required check fails the workflow when its requirement is violated. Advisory checks are named and reported as advisory.

**CICD-034 — Coverage as evidence.** Coverage thresholds MAY protect against regression but MUST NOT replace risk-based tests. Generated code and unreachable platform code are handled explicitly.

## ARTIFACTS AND RELEASES

**CICD-040 — Build once where feasible.** Release consumes the tested artifact. Rebuild is allowed only when reproducibility is verified and the exact source and toolchain are preserved.

**CICD-041 — Version source.** A release has one version authority. Tags, package metadata, images, and release notes derive from it.

**CICD-042 — Protected publication.** Publication and deployment require successful prerequisite checks and environment policy. Manual dispatch does not bypass validation.

**CICD-043 — Rollback.** Deployable systems identify rollback or safe-forward recovery and retain the artifact or metadata needed to perform it.

## MAINTAINABILITY

**CICD-050 — Reuse without opacity.** Reusable workflows and composite actions SHOULD remove duplication while keeping inputs, permissions, outputs, and failure behavior visible.

**CICD-051 — Generated facts.** Action versions and dependency catalogs are generated by `scripts/dependency_catalog.py`. A freshness check prevents manual drift.

**CICD-052 — Local parity by purpose.** Developers need commands that reproduce relevant checks. Local pre-commit does not have to execute every CI job.

**CICD-053 — Evidence in PRs.** Workflow changes report files changed, threat boundary, validations run, and checks intentionally deferred.

## ACCEPTANCE

A compliant pipeline proves the tested source, required quality gates, trust boundaries, artifact identity, publication permissions, and recovery path. Exact filenames and job counts are project choices.
