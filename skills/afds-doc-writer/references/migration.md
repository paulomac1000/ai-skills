# AFDS migration

1. Inventory documents, generated files, duplicate topics, broken links, and stale instructions.
2. Build a fact ownership map before rewriting prose.
3. Mark generated and historical content; do not hand-edit it into canonical docs.
4. Convert high-risk workflows and contracts first.
5. Merge duplicates only after comparing their evidence and consumers.
6. Preserve redirects or deprecation stubs for stable IDs.
7. Run structural validation, mutation tests, and retrieval benchmark.
8. Delete compatibility scaffolding after all consumers migrate.

A migration report must list retained knowledge, removed duplication, unresolved conflicts, and validation evidence.
